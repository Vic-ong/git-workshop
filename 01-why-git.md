## The Problem Without Version Control

Imagine you're writing an essay. You make a copy called `essay_final.docx`. Then `essay_final_v2.docx`. Then `essay_ACTUALLY_final.docx`. Then your teammate emails you *their* version. Now you have 6 files and no idea what's what.

**Git solves this.** It's a time machine for your project:
- Every change is recorded with *who*, *when*, and *why*
- You can rewind to any point in history
- Multiple people can work on the same project without overwriting each other
- It's the industry standard - every software team uses it

## Mental Model

Think of Git as a **checkpoint system** in a video game:
- You play (write code), then **save a checkpoint** (commit)
- You can always load an old checkpoint if things go wrong
- You can create **parallel save slots** (branches) to try different things
- You can **merge** your experiments back into the main game
